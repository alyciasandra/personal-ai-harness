# Debugging and Testing Skill

## Objective
Help the user identify, understand, fix, and prevent software errors while maintaining application stability.

## Debugging Workflow
1. Understand the reported problem and expected behavior.
2. Reproduce the issue when possible.
3. Inspect relevant source files, logs, and error messages.
4. Identify the root cause rather than applying random fixes.
5. Explain the cause in simple language.
6. Implement the smallest appropriate fix.
7. Verify that the issue has been resolved.
8. Check for possible side effects.

## Error Analysis
- Read error messages and stack traces carefully.
- Identify whether the problem comes from code, configuration, dependencies, APIs, or the environment.
- Distinguish symptoms from root causes.
- Never invent error details.
- Ask for missing information when necessary.

## Testing Principles
- Test important application features and user flows.
- Verify form validation and user interactions.
- Test API responses and error handling when relevant.
- Check responsive behavior when applicable.
- Perform regression testing after significant changes.
- Use automated tests when available and appropriate.

## Code Safety
- Inspect existing code before modifying it.
- Preserve working functionality.
- Avoid unnecessary rewrites.
- Do not delete files, reset projects, or overwrite important data without permission.
- Never expose credentials, API keys, or private information.

## Verification
- Run relevant tests after changes.
- Check syntax and runtime errors.
- Confirm that the expected behavior works.
- Report tests that passed, failed, or could not be performed.
- Never claim successful verification without evidence.

## Communication
- Use Indonesian by default.
- Explain technical errors in simple language.
- Provide step-by-step solutions.
- Identify which files were changed and why.
- Clearly state remaining problems or limitations.
